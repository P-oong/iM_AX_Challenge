## 프로젝트 개요

은행 영업점의 KPI는 수십 개 지표와 계단식 배점 체계로 이뤄져 있지만, 현장은 이를
정적인 엑셀 문서로만 전달받아 온전히 소화하지 못합니다. 결국 익숙한 몇 개 지표만
관리되고 나머지는 사각지대로 방치되며, 관리 노하우는 특정 책임자 개인에게 귀속되어
**인사이동 때마다 지점의 실적 관리 역량이 리셋**됩니다.

본 서비스는 **부문별 전문 AI 에이전트**가 매주 전체 지표를 분석해 "지금 무엇을 하면
점수가 가장 많이 오르는지"를 브리핑하고, 지점장의 피드백을 학습해 **그 지점만의
에이전트로 진화**하는 시스템입니다.

### 설계 원칙 — "판단은 AI가, 계산은 엔진이"

금융 KPI는 1점 차이로 등급이 갈리므로, **점수·구간·ROI 계산은 100% 결정론적
연산엔진(Python)이 수행**하고 LLM은 규정 해석·전략 수립·자연어 브리핑만 담당합니다.
에이전트가 인용한 모든 수치는 **Validator가 엔진 원본과 전수 대조**하며, 불일치
발견 시 해당 부문만 자동 재분석합니다. Validator 역시 LLM이 아닌 결정론적
Python입니다 — 수치 검증을 다시 LLM에게 맡기면 원칙이 무너지기 때문입니다.

## 시스템 아키텍처 (LangGraph 멀티에이전트)

30개 지표를 하나의 프롬프트에 몰아넣으면 정보량에 눌려 내용을 누락하거나 부문별
규칙을 혼동하는 **'지시 희석 현상'**이 발생합니다. 이를 막기 위해 부문별로 전문
에이전트를 나누고, LangGraph가 병렬 실행·검증·종합을 오케스트레이션합니다.

```
START → dispatch ─┬─▶ 수신 에이전트 ───┐
                  ├─▶ 여신 에이전트 ───┤  (Send fan-out, 병렬 실행)
                  ├─▶ 외환 에이전트 ───┤
                  └─▶ 기업연금 에이전트 ┘
                            │
                            ▼
                     Validator ◄──── 문제 발견 시 해당 부문만 재실행
                            │ 통과
                            ▼
                     Supervisor (최종 3대 과제 확정)
                            │
                            ▼
                     최종 Validator ◄─ 문제 시 재실행
                            │ 통과
                            ▼
                           END
```

- **부문 에이전트**: 자기 부문 지표만 보고 추천 후보를 상정 (부문 특화 판단 로직 내장)
- **Validator**: 수치 환각·부문 월경·상한도달 지표 추천·허위 영업중단 권고 등을 검출
- **Supervisor**: 부문별 안건을 동일 척도(점/건)로 비교, 편중 없이 3대 과제 확정
- **지점 특화 진화**: 동일 (부문·사유) 보류가 3회 누적되면 지점 고유 규칙으로 승격 →
  다음 브리핑부터 해당 부문 가중치 하향 + 우회 전략 제안

## 주요 기능 (화면)

| 화면 | 기능 |
|---|---|
| **홈** | 지점 현황 요약(총점·전주대비), 핵심 기능 안내, 에이전트 라인업 소개 |
| **① 주간 전략 브리핑** ⭐ | 3대 과제 카드(제안 에이전트 배지·상세 배점표·규정 원문), 수용/보류 피드백, 전 직원 메신저 전송, 부문별 안건→채택 현황, Validator 검증 로그 |
| **② 지표 현황 히트맵** | 30개 지표를 상한도달/진행/가성비/사각지대로 색 구분 시각화 |
| **③ KPI 시뮬레이터** | "이 지표 N건 추가 시" 총점 변화 즉시 계산 (LLM 미개입) |
| **④ 규정 Q&A 챗** | 자연어 규정 질의 — 근거 문서 없으면 답변 대신 "규정 확인 필요" 반환 |
| **⑤ 피드백 로그** | 누적 수용/보류 이력과 학습된 지점 고유 규칙 확인 |

## 데이터 안내

모든 실적·지점·피어그룹 데이터는 `src/data_generator.py`가 **시드 기반으로 생성하는
가상 데이터**입니다 (실제 고객/거래 정보 없음). 사이드바에서 시드를 바꾸면 다른 지점
시나리오가 재현되며, **KPI 규정과 평가 기준은 시드와 무관하게 항상 동일**합니다.
피드백 로그는 데이터를 재생성해도 유지됩니다 — 인사이동과 무관하게 축적되는
'지점 메모리' 컨셉의 반영입니다.

## 실행 방법

```bash
pip install -r requirements.txt
streamlit run Home.py
```

- OpenAI API 키 없이도 전 화면이 폴백(결정론적 템플릿)으로 정상 동작합니다.
- 실제 LLM 브리핑/Q&A를 쓰려면 `.env.example`을 `.env`로 복사해 `OPENAI_API_KEY`를
  채워주세요. 배포(Streamlit Cloud) 시에는 대시보드 → Settings → Secrets에
  `OPENAI_API_KEY = "sk-..."`를 등록하면 동일 코드로 동작합니다.
